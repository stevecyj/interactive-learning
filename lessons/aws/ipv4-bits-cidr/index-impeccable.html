IPv4 × CIDR

01 / 先分清名稱與地址

IPv4 的 4，是版本 4

IPv4 = Internet Protocol version 4，中文是「網際網路協定第 4 版」。它定義資料如何利用地址，在網路間傳送。

協定的名字

IPv4

v4 表示第 4 版

一個 IPv4 地址的例子

10.0.1.0

4 組十進位數，每組 0～255

地址規格
32 bits 是 IPv4 規格定下的長度。它不是從畫面上有幾個十進位數字算出來的。

接下來把一個地址拆開，你就會看見這 32 個位置。

02 / 最小的一格

1 個 bit，只能放 0 或 1

bit 是「二進位的一個位元」。它是一個位置，不是十進位數字的位數。

點一下，切換 0 / 1

這一格共有 2 種狀態

00 01 10 11

如果有 2 格：2 × 2 = 4 種組合

組合數
每多一個 bit，組合數就乘以 2。8 個 bit 就是 2 連乘 8 次。

03 / 一組地址的內部

8 個 bit，可以表示 0～255

先看熟悉的 111：同樣是「1」，放在百位代表 100，放在十位代表 10，放在個位才代表 1。二進位也是看位置，只是每一格代表的數值不同。

熟悉的十進位：111

百位：這格代表 10011 × 100
十位：這格代表 1011 × 10
個位：這格代表 111 × 1

100 + 10 + 1 = 111

換成二進位：1010

這格代表 811 × 8
這格代表 400 × 4
這格代表 211 × 2
這格代表 100 × 1

8 + 0 + 2 + 0 = 10

二進位 1010，和十進位 10，是同一個數值。

現在擴成 8 格，換你來選

8 個 bit 叫作一個 octet。上排是「這一格代表的數值」；下排按成 1 就選取，按成 0 就不選。把選到的數值加起來，就是十進位的答案。

1286432168421
把選到的數值加起來
同一數值的十進位寫法

1010 前面補 0，寫成 8 格的 00001010，值不變：仍然只選了 8 和 2，所以是 8 + 2 = 10。

255最大的值
256總共幾種值（包含 0）

00000000 到 11111111，共 2⁸ = 256 種。255 只是最大值，不是組合數。

04 / 把四組並排

4 組 × 每組 8 bits = 32 bits

10.0.1.0 是方便人閱讀的寫法。每一組數字，都可以展開成 8 個二進位位置。

8 + 8 + 8 + 8 = 32

255.255.255.255 看起來有 12 個十進位數字，但每個 255 都對應 11111111。地址仍然是 32 bits；分隔點不算地址的 bit。

所以不是「IPv4 有 8 個數字」，而是「4 組數，每組用 8 個 bit 表示」。

05 / 選出同一個地址區塊

/24：前 24 個 bit 要相同

以 10.0.1.0/24 為例，前 3 組是這個區塊的共同前綴。最後 8 個 bit 可以變動。

共同前綴
「固定」是指這個區塊內的地址共享相同前綴。不是說你的 IP 永遠不能改；前綴中的值可以是 0，也可以是 1。

遮罩本身是 32-bit 的選取模式；「套用遮罩」則是拿這個模式與 IP 做計算。

遮罩用途
遮罩讓我們只看需要的部分，忽略其餘部分。這裡選出的是網路部分；它不會隱藏你的 IP，也不會授予連線權限。
想看精確的計算規則？

這個操作叫逐位元 AND。每個位置各算一次：

IP 0 AND 遮罩 1 → 結果 0IP 1 AND 遮罩 1 → 結果 1IP 0 AND 遮罩 0 → 結果 0IP 1 AND 遮罩 0 → 結果 0

AND 表示兩邊都是 1 時，結果才是 1。遮罩為 1 時保留原值；為 0 時，衍生結果的該位置是 0。

08 / 用同一片遮罩看不同 IP

算完網路位址，就能比較分組

三台機器的完整 IP 都不一樣。套用相同遮罩後，網路位址相同的，就落在同一個 CIDR 區塊。

三台一起套用：

遮罩說：看哪些位置

255.255.255.0

單看遮罩，不知道是 10.0.1 還是 10.0.2。

IP 說：那些位置是什麼值

10.0.1.37 + /24

兩者一起，才得到 10.0.1.0/24。

這種分組可用來判斷地址所屬網路，並支援路由判斷。實際能不能互通，還要看路由、網路連接與安全規則；同一區塊不保證一定能連線。

規格參考：RFC 791 §3.1、§3.2（32-bit IPv4 地址） · RFC 4632 §3.1（CIDR 前綴）

09 / 分界不一定在點上

CIDR 遮罩：左邊連續 1，右邊全是 0

/24 是常見選擇，不是所有網路的通用預設。分界可以落在 32 個位置中的任一處，包括一組 8 bits 的中間。

為什麼 255.255.191.0 不能寫成單一 /n？

看第 3 組：191 = 10111111。出現 0 之後，又出現了 1。

紅框標出破洞。第 18 bit 是 0，後面第 19～24 bits 卻又是 1。這不是「先連續 1，再全部 0」的一條分界，因此不是單一 CIDR 前綴的遮罩。

不能只數出 23 個 1 就叫它 /23。真正 /23 是 23 個連續的 1：255.255.254.0。這是兩種不同的位元模式，不能默默把 191 改成 254。

/0、/31、/32 也算有效嗎？

/0 的遮罩全為 0，表示沒有固定前綴；/32 全為 1，只指定一個地址。/31 是有效前綴，RFC 3021 說明它在 IPv4 點對點連線的使用方式。

「有效 CIDR 前綴」不等於「每個平台都能拿它建立子網路」。例如 AWS 的子網路大小另有規則；這一頁只展示 CIDR 遮罩的連續性。

規格參考：RFC 4632 §3.1：前綴長度與遮罩 · RFC 3021：/31 點對點連線
