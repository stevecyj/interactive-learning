# 循序漸進的 HTML 互動教學

請把以下主題製作成「循序漸進的 HTML 互動教學」，幫我理解原理，最後能用在實際情境。

若需求已寫在該教學的 `brief.md`，請以該檔案取代下方的需求欄位；相關來源見該教學的 `references/`。

## 我的需求

- 主題：〔填入〕
- 我目前懂到：〔填入，完全不懂也可以〕
- 我卡住的地方：〔描述看不懂、覺得矛盾或無法對應的部分〕
- 學完後想能做到：〔一個真實任務或判斷〕
- 參考資料：〔選填：文字、圖片、網址或既有 HTML〕
- 樣式參考：〔選填：既有 HTML 的路徑或附件；未指定時自行設計〕

參考資料用來確認內容；樣式參考用來確認視覺呈現。同一份 HTML 若兼具兩種用途，請明確標示。學習程度或卡點未提供時，可以依目標安排入門順序，但應將假設標為假設。

## 教學方式

1. 從我的卡點找出缺少的前置概念，先補上，再往下教。每一步聚焦一個核心問題，不要一開始就塞入完整知識體系。
2. 將抽象文字轉成能看見的對應：原本的寫法、展開後的結構、各部分的意義，放在一起比較。
3. 先讓我只改變一個條件，立即看到圖形、數值（若有）與結果如何連動；需要綜合判斷時再加入其他條件。明確標示「我改了什麼、哪些保持不變、結果為何改變」。互動要幫助理解，不只是按下一頁換文字。
4. 說清楚「哪些是定義、哪些是推導結果、哪些是特定情境的規則」，並標示規則的適用條件。有數字時，標示它算的是什麼、單位及必要的計算過程，不要直接丟出公式和答案。
5. 先用最簡單的例子建立理解，再加入容易混淆的對照例子。必要術語在第一次出現時，用白話解釋。
6. 圖像、比喻和版面請自行設計，但必須忠於原理。固定與變動的部分要有明確標記，不能只靠顏色辨識。

## 樣式參考

有指定樣式參考時，先讀取該 HTML；有可用瀏覽器時也查看實際呈現。沿用其配色、字體層級、留白、卡片與導覽風格，教學圖像及互動依新主題重新設計。參考範例的主題內容、頁數與計算規則不會因此成為新教學的要求。

未指定樣式參考時，採清楚、少干擾的設計。內容正確性、可讀性與操作需求優先於視覺相似度。

## 最後的練習

設計 3 題貼近我的目標的情境題，由容易到需要綜合判斷。

讓我先作答，再揭曉答案；未作答時先提示完成作答。解答依序呈現「標出題目條件 → 在圖中比對關鍵位置 → 套用原理或規則 → 得出判斷」，指出為什麼成立或不成立。可以用編號圖解或逐步揭露，不必每題都做動畫。答錯時指出所選答案錯在哪個判斷，並允許重新作答。

## 交付與檢查

- 交付單一 HTML 檔，CSS、JavaScript 與必要圖像均內嵌，可用瀏覽器直接開啟、離線使用，不依賴外部套件、CDN 或網路請求。來源連結可連網開啟，但不影響離線教學。
- 採清楚、少干擾的動態簡報形式，提供上一步／下一步。切換步驟時保留已操作的狀態；探索互動提供重設方式。圖形、數值與結論由同一份狀態與計算結果更新。
- 適合電腦和手機，按鈕、輸入與練習都可用鍵盤操作，焦點位置清楚。若提供換頁快捷鍵，在輸入框或滑桿操作時，應保留該控制項的按鍵用途。動畫遵循減少動態效果的系統偏好。
- 根據參考資料核對教學內容；涉及會變動的平台規則時，查閱官方來源並記錄查閱日期。資料無法取得或規則未確認時，標示不確定處。
- 檢查範圍：典型例子、容易混淆的對照例子，以及適用的最小值、最大值與無效輸入；確認圖形、數值和結論一致。
- 有可用瀏覽器時，直接開啟檔案，操作所有互動與 3 題練習，檢查未作答、答對、答錯及重試狀態，以及第一步／最後一步、回到上一步、重設、窄螢幕與鍵盤操作。確認離線時必要資源仍可使用。
- 交付時列出檔案位置與實際檢查結果；未驗證項目請明說。若在本專案內製作，將結果記入該教學的 `brief.md`。
- 除非缺少會影響教學方向的關鍵資訊，否則自行合理安排並完成，不必逐項詢問我設計偏好。
